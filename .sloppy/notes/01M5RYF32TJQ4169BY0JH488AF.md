## What it is for

At creation a note is offered an address by the Folgezettel rule: a branch takes the next whole number, a child alternates segment type (`1` → `1a` → `1a1`), a sibling increments the last segment. The rule offers the next address after the greatest ever assigned in the run, so a number a deleted, purged or moved note spent is never offered again. A sibling with no address is not in the run and never moves what the rule offers. A person may name the address instead; a named one is held to every rule a written label is, and must spring from the address of the note above, or from nothing where the note opens a branch.

Two peers applying the same operations must reach byte-identical suggestions. [The determinism suite](code:packages/ts/types/src/address.test.ts#L925-L990) replays generated sequences of writing, deleting, purging and moving through two peers built on unrelated internal state — one keeping each run's high-water mark, one holding nothing but addresses — and compares them. `addressing.test.ts` in `@sloppy/local` makes the same claim against a graph held on a device.

## Why

AI.md § "The Genealogy Is the Protocol (required)": "Two peers applying the same creation operations must produce byte-identical suggestions, so the rule ships as a property test over generated operation sequences rather than a handful of hand-picked cases." docs/ARCHITECTURE.md § "The genealogy and the address" says why a hand-written label is not one of those operations: the replica holding only addresses "recovers a run from the addresses themselves, and a label is not a place in the tree"; what the server does with one is held in `node.service.test.ts` and `domain.integration.test.ts`.
