## What it is for

A person writes down what they want, as exactly as they can say it, and the code grows out of what is written — with or without something set to work beside them, on either half. So a note is not a record filed after a decision; it is the intent the code is answerable to, and the check between them runs in both directions. Two things follow that a person can rely on. A version of the project is somewhere they write from, not only somewhere they look. And pressing **Build** on a note plans the work from what the notes say and asks what they do not before anything is written; [the build store](code:packages/ts/app-core/src/lib/stores/build.svelte.ts#builds) runs those phases.

## Why

[AI.md](code:AI.md) § "Project": "the documents come first: this is a tool for intent-driven development", and "a note is not a record filed beside the code after the decision was taken. It is the intent the code is answerable to, which is why the check runs in both directions". [PRODUCT.md](code:PRODUCT.md) § "Product Purpose" adds that "neither half is the senior one". [README.md](code:README.md) § "Documentation-driven development" gives the reason it matters now: "If a machine is going to write a large share of your code, the honest question is not whether it wrote good code, but what it was told, what it wrote, and whether the result matches what the note said the thing was for".
